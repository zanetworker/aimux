# Project context: aimux iPhone app (clients/ios)

Living summary of where the iPhone app stands, why it is the way it is, and what is open. The app lives in the aimux repo at `clients/ios`, next to the phone web client (`clients/web`) and the contract both use (`api/remote-v1.openapi.yaml`). aimux's own guide is `.claude/CLAUDE.md` at the repo root. Kept up to date by the project-context skill (`/project-context save`). Per-session logs are in `docs/sessions/`. Last updated: 2026-10-28.

## Purpose

Native iPhone app (SwiftUI) for aimux's remote API v1, so the owner can find, follow, continue and start Claude Code sessions on their Mac from the phone, by touch or voice, and answer permission requests. Design: `docs/superpowers/specs/2026-10-26-aimux-ios-design.md` (repo root); plan: `docs/superpowers/plans/2026-10-26-clients-move-and-now.md`; API brief: `docs/brief.md` (this folder).

## Rules and constraints

- Talk only to `/v1`; ignore unknown fields and keep unknown enum values (`Models.swift`, `APIError.swift`).
- No `Origin` header; identity comes from Tailscale, and with device login from the paired Secure Enclave key (`APIClient.swift`, `DeviceLogin.swift`). The session token never leaves memory.
- Sessions open in a terminal on the Mac, and sessions that never started, are read only in the chat (`ChatModel.load`), as in the web client, unless the server sends `terminal` (terminal input, Version 0.3 (7)): then the chat polls the history (2 s while busy or for 2 minutes after a send, else 15 s), shows the composer while `terminal.canType` and otherwise the reason line, types messages through `terminal/messages` (pending "Sent to your Mac's terminal", "Sent; no answer yet" after 2 minutes; cleared by a history turn even when Claude Code wrapped it), and shows `terminal.prompt` as an approval card answered through `terminal/keys`. A terminal send is never retried automatically: a timeout can leave partial input.
- Approvals are answered by tap only, never by voice.
- Never commit real session titles or prompts in fixtures; never commit the owner's tailnet address (the app asks for it at first launch; tests use `my-mac.tail1234.ts.net`).
- Near-monochrome UI: colour only in status dots; no rainbow, emoji, initials badges or gradients.
- The web client follows the same design as the app; ranking rules are shared fixtures, never reimplemented per client without them.
- aimux rules apply: no commit or push without the owner's approval; push with `git ship`.

## Key decisions and why

- Native SwiftUI inside aimux (`clients/ios`), not a separate repo or a WebView shell: most features need API, server and app changes in one PR. Moved before build step 1.
- All clients under `clients/`, one contract, CI filtered by path.
- Ranking (needs you, working, finished, failed, grouping above 5 working, the On your Mac cap) is written once as JSON fixtures in `api/testdata/clients/`, run by Swift and web tests; the server reports state, clients rank.
- Home screen: Now and All tabs plus a search button; rank by what you can act on. Rejected: cards, flat list, avatars, chips, segmented switch, custom dock.
- Now polls `GET /v1/sessions` every 15 s while visible plus one `events?wait=0` snapshot per busy API-driven session; live streams only inside a chat.
- XcodeGen with logic in a framework target (testable without the app; a local Swift package breaks Xcode previews).
- Codable types written by hand from the contract: about 15 schemas and the compatibility rules need custom decoding.
- Custom timestamp parser: Go sends 0-9 fractional digits, which Foundation's `.iso8601` rejects.
- Deployment target iOS 27.0, the owner's phone.
- `feat/clients` tracks `origin/main` so `git pull` brings in main; rebase only before the first push.

## Research results

- The server listens on 127.0.0.1 and rejects direct requests (`untrusted Host`); test through the tailnet URL.
- The owner has about 330 sessions in 24 projects, 250 of them in `research`: a flat newest-50 list was unusable. All 500 load in about 0.3 s; server search takes 1.7-4 s.
- On iOS 27 (simulator) `Tab(role: .search)` draws Search inside the tab pill, not as the separate round button of the mockups; `.sidebarAdaptable` and `.searchable` on the TabView did not change that.
- On iOS 27 an active search replaces the toolbar with a single "Close" button, hiding the project menu until search ends.
- Claude Code 2.1.311 draws a permission prompt as "Do you want to create live.txt?", options 1 Yes, 2 "Yes, and switch to accept edits ...", 3 No, then the footer "Esc to cancel · Tab to amend" with nothing below it. A message typed while idle is saved as typed, also when it has two lines or 300 characters (no `<pasted_content>` wrapper); a message typed while busy is saved as a `queue-operation` plus an `attachment` of type `queued_command` (seen live), which the history parser turns into its own turn (`parseClaudeQueuedCommand` in `internal/provider/claude.go`). The `<pasted_content>` wrapper and the "while you were working" prefix have not been seen live; the clients still unwrap both, which is harmless.
- tailscale serve answers 502 with an empty body when aimux is not running; the app says "aimux isn't running".
