# aimux iPhone app (`clients/ios`)

Rules for coding agents (Claude Code, Codex, Cursor, Gemini CLI) working on the iPhone app in this folder.

## Purpose

Native iPhone app (SwiftUI) for aimux's remote API v1: find, follow, continue and start Claude Code sessions on the owner's Mac, answer permission requests, by touch or voice. Talks only to `/v1` over the tailnet (contract: `../../api/remote-v1.openapi.yaml`; design: `../../docs/superpowers/specs/2026-10-26-aimux-ios-design.md`; starting brief: `docs/brief.md`). When a feature needs a server change, change the contract and the Go code in the same branch.

- `project.yml` is the source; the `.xcodeproj` is generated by `xcodegen generate` and not committed.
- Logic lives in the `AimuxKit` framework (no SwiftUI) and is tested there with Swift Testing; views are checked by simulator screenshots.
- Test fixtures copy live payload shapes with the session text replaced; never commit real titles or prompts.
- Device login: the Secure Enclave key is made with `.privateKeyUsage` and `.biometryCurrentSet`; the session token stays in memory, never in UserDefaults, the Keychain or a file; tests and the simulator use `SoftwareKeyStore` behind the same `DeviceKey` protocol. Never log or show a pairing code, challenge or token.

## Layout

- `AimuxKit/Sources/`: the framework (API client, models, events, approvals, Now ranking and model, All sections, timestamps, device key and device login); no SwiftUI.
- `AimuxKitTests/`: Swift Testing tests and JSON fixtures; the shared ranking fixtures come from `../../api/testdata/clients/`.
- `App/`: SwiftUI screens (`NowView`, `AllView`, `SearchView`, `ChatView`, `RootTabs`, settings, `PairingView`, `UnlockView`) and `App/Components/` (header, rows, approval card, status dot, timeline rows, composer, Next bar, session info sheet); `DebugHooks.swift` holds the `-demo`, `-tab`, `-openChat`, `-openInfo`, `-openSteps`, `-openStepDetails` and `-deviceLogin` launch arguments for screenshots and UI tests.
- `UITests/`: XCUITest flows on the demo data.
- `docs/`: brief, project context and session logs. The code map is in `README.md`.

## Build

- in `clients/ios`: `xcodegen generate && xcodebuild build -scheme Aimux -project Aimux.xcodeproj`

## Test

- in `clients/ios`, tests (logic and UI) on a simulator: `xcodegen generate && xcodebuild test -project Aimux.xcodeproj -scheme Aimux -destination "id=<simulator UDID>" -derivedDataPath build/sim -collect-test-diagnostics never` (list simulators with `xcrun simctl list devices available`; the deployment target is iOS 27.0)
- logic tests only: add `-only-testing:AimuxKitTests`
- web client tests, from the repo root: `node --test "clients/web/webapp/*.test.mjs"`
- in `clients/ios`, lint: `swiftlint lint --strict`
- in `clients/ios`, vulnerabilities: `osv-scanner scan source -r .`

## Conventions

- Run `pre-commit run --files <changed files>` from the repo root before committing; the swiftlint hook covers `clients/ios/`.
- Never commit secrets, tokens or credentials files; gitleaks runs in pre-commit and in CI.
- Add or update tests with every behavior change and keep the test commands above green.
- Keep changes small and focused; match the existing style of the file you edit.
- CI (`.github/workflows/clients-ios.yml` at the repo root) runs `swiftlint lint --strict` and the AimuxKit logic tests on a `macos-26` runner with Xcode 27 when `clients/ios/**` or `api/**` change.
- Ranking rules for Now and All are shared JSON fixtures in `../../api/testdata/clients/`, run by both the Swift and the web tests; change the fixture first, then both clients.
