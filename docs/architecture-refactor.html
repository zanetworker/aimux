Self-Hosted Agent Management Platform

Three-axis separation: Provider (what) + Environment (where) + Coordination (how)

SEPTEMBER 2026 · 6 PHASES COMPLETE · 22 COMMITS

Vision

aimux is a self-hosted agent management platform. It discovers running AI agents, manages their lifecycle across local and remote environments, and coordinates multi-agent work through a unified interface available as TUI, web dashboard, CLI, and MCP server.

The architecture separates three independent concerns. Changing where agents run does not change what agents are or how they coordinate. Each axis has its own Go interface, multiple implementations, and independent tests.

Three Axes

Provider
Identity of an agent runtime. Slimmed to identity-only: name, spawn command, trace parser, OTEL env vars. No infrastructure methods.
Environment
Where agents execute. Owns discovery for remote agents, sandbox lifecycle (create, list, kill), and health checking. Three implementations: Local (fork/exec), OpenShell (NVIDIA sandbox), K8s (pod + Redis heartbeat).
Coordinator
How agents collaborate. Task creation, message passing, heartbeats, cost aggregation. In-memory for solo use (zero config), Redis for multi-node. MCP server delegates all operations here.

Current Architecture

CLI Surface

Every axis is inspectable from the command line. All commands support --json for scripting.

Discover

aimux agents                           # list running agents
aimux agents --json --filter claude    # filtered, machine-readable
aimux environments                     # list configured environments
aimux envs --check                     # test connectivity
aimux configs                          # list named agent configs

Launch

aimux spawn claude                     # raw provider, local
aimux spawn reviewer                   # named config from agents.yaml
aimux spawn claude --environment sandbox   # explicit environment
aimux spawn reviewer --dry-run         # preview without launching

Manage

aimux kill <pid>                       # terminate an agent
aimux sessions                         # browse past sessions
aimux resume <session-id>              # resume a session
aimux export <session-id>              # export trace (JSONL/OTEL)

Configuration

Environments (~/.aimux/config.yaml)

environments:
  local:
    type: local
  sandbox:
    type: openshell
    gateway: "https://gateway.example.com"
    image: "ghcr.io/.../sandboxes/base:latest"
  cluster:
    type: k8s
    redis_url: "redis://redis.agents.svc:6379"
    namespace: agents

Named Agent Configs (~/.aimux/agents.yaml)

- name: reviewer
  runtime: claude
  model: opus
  prompt: "Review code for bugs and security issues"
  mcp: [github]

- name: writer
  runtime: codex
  model: o3
  prompt: "Write comprehensive tests"

Project-local .aimux/agents.yaml overrides global configs by name. Use aimux spawn reviewer to launch by name.
