Vision

aimux is a self-hosted Claude Managed Agents (CMA) equivalent. Anthropic runs the agent loop and hosts the sandbox. aimux does the same, but on your infrastructure: OpenShell runs the sandbox, agent-compose binds agent configs to environments, Redis coordinates tasks and messaging.

The current codebase conflates three concerns: what an agent is (Claude vs Codex), where it runs (local vs K8s vs OpenShell), and how tasks flow (Redis queues, messaging, heartbeat). Untangling these into three clean axes is the refactor.

agent-compose as the Binder

agent-compose connects Agent configs to Environments. It resolves declarative references (runtime, inference, MCP, policy, skills) into a concrete ResolvedSpec that the Environment's Executor can create a sandbox from. aimux currently bypasses this pipeline. The refactor promotes it to the primary launch path.

Resolution Flow

Agent YAML
Declarative config: runtime: claude, inference: anthropic, mcp: [github], skills: [code-review], policy: restricted
Engine.Resolve()
Flattens references into a ResolvedSpec: concrete image, entrypoint, env vars, egress endpoints, MCP configs, skill mounts
Executor
Creates the sandbox from the ResolvedSpec. LocalExecutor forks a process. CLIExecutor calls openshell sandbox create. K8sExecutor creates a pod.

What OpenShell Owns

OpenShell IS the environment. It creates and manages sandboxes with deny-by-default networking, provider backends (Podman, K8s, remote), and policy enforcement. agent-compose injects the agent config INTO the OpenShell sandbox: env vars, MCP config file, skill mounts, egress rules, and the entrypoint.

Progressive Disclosure

  1. Tier 1: Solo Developer (zero config). Pick a harness (Claude, Codex) in the launcher, press enter. LocalExecutor forks a process. Sessions tracked via process scan + JSONL files. No environments config, no agents.yaml, no Redis. Identical to today's experience.
  2. Tier 2: Team with OpenShell (add gateway config). Add an environments section to config with a named OpenShell gateway. The launcher shows environment selection alongside harness selection. agent-compose resolves the runtime + policy into the sandbox. Sessions tracked locally + via openshell sandbox list.
  3. Tier 3: Platform Operator (full config). Add named agent configs in agents.yaml (prompt, skills, MCP, inference, policy). Add Redis coordination. Named agent configs appear in the launcher alongside raw harness names. Sessions persist in Redis. MCP server exposes spawn_agent, create_task, send_message. Self-hosted CMA equivalent.

Package Structure

provider/
Identity only. Claude, Codex. ParseTrace, FindSessionFile, SpawnCommand, CanEmbed, OTELEnv. No Discover(), no Kill(). openshell.go deleted.
environment/
Compute + discovery. Local (fork + ps scan), OpenShell (default remote; CLI executor upgradeable to Go SDK / RPC), Raw K8s (opt-in, no sandbox governance). Implements Environment interface.
coordination/
Task flow. Redis implementation (extracted from k8s.go + mcpserver). Local fallback (in-memory). Implements Coordinator interface.
session/
Lifecycle management. Session struct, store, manager. Replaces 3-field LaunchMeta. Create/track/resume/archive.
frontend/tui/
Thin adapter. app.go as thin router (~500 lines). Sub-coordinators: AgentCoord, SessionCoord, TraceCoord, LaunchCoord.
mcpserver/
MCP tools. Talks to Coordinator interface, not Redis directly. spawn_agent, create_task, send_message, list_agents.
controller/
Unchanged. Shared business logic: sort, filter, attend, export, etc.
terminal/
Unchanged. SessionBackend: PTY embed, tmux mirror, openshell connect.

Implementation Phases

One branch per phase. Each is self-contained and independently reviewable. Tests pass at every phase boundary.

  1. Phase 1: Extract Environment from Provider. Create environment/ with the interface. Move K8s infra into environment/k8s.go. Consolidate OpenShell scatter (5 packages) into environment/openshell.go. Create environment/local.go. Delete provider/openshell.go. Remove infra methods from Provider.
  2. Phase 2: Extract Coordination. Create coordination/ with Redis + Local implementations. Move Redis from provider/k8s.go and mcpserver/server.go. Update MCP server to use Coordinator interface. Wire both K8s and OpenShell environments to register in Redis.
  3. Phase 3: Promote agent-compose. Route all launches through Engine.Resolve() + Engine.Run(). Add LocalExecutor. Add named environment configs. Update launcher with environment selection.
  4. Phase 4: Managed Sessions. Create session/ with Session struct + lifecycle. Replace LaunchMeta. Wire through agent-compose pipeline. Add persistence (local + Redis).
  5. Phase 5: Named Agent Configs. Add agents.yaml loading. Show named configs in launcher alongside raw harness names. Wire agent-compose resolution. Expose through MCP server and web API.
  6. Phase 6: Decompose app.go. Extract AgentCoordinator, SessionCoordinator, TraceCoordinator, LaunchCoordinator. app.go becomes thin router (~500 lines).
