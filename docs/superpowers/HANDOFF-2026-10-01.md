## Design state

Spec: `docs/superpowers/specs/2026-09-10-backend-architecture.md` (Codex-reviewed). Key decisions:
- Interfaces: `Sessions` (Create/Get/List/Send/Abort/Pause/Resume/Subscribe), `Agents` (List/Get/Create/Update/Delete), `Sandboxes` (List). Plain verbs, no Run type, namespaced `Ref{Backend,ID}`, cursor-based EventStream, json.RawMessage events
- Named backends in config (`backends: {local, my-server: {type: openclaw, endpoint}}`), agent `backend:` default, `--backend` override, `aimux backends add|list|remove`
- Four state layers (workspace, session, harness, platform); crash recovery is a backend quality; single-writer enforced by backend
- Aligned with OpenAI Agents API and CMA (same agent/session/sandbox model)

## Conclusions from the latest discussion

- aimux = personal agent OS for the developer (TUI/Web/CLI, later mobile). Not a platform, not a harness.
- Each harness gravitates to its own management plane (OpenClaw to OCC, Mecatl to its own, Codex to OpenAI Agents API). Don't build a generic management plane; aimux consumes whichever pair.
- OCC is open source: https://github.com/openclaw/openclaw-enterprise (TS controller + Go CLI/client `internal/occclient/`, REST/OpenAPI, Docker/K8s/SSH compute drivers, OpenShell sandbox driver, gateway per namespace). No session state/leasing/snapshots; those stay in the gateway.
- aimux needs two connections for OCC: OCC REST (agents, deploy, namespaces) + namespace gateway WebSocket (sessions, events).
- Corrections to the UX draft: deploy is per agent, not per session; session pause/resume doesn't exist in OCC/OpenClaw; gateway reachability/auth from outside the cluster is unverified; `agents publish` mapping is lossy.
