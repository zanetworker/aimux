# Finding sessions from the phone

Both phone clients, `aimux remote serve`, and aimux's shared session metadata.

## Intent

The owner could not find a session on the phone. Its title came from its first message, which was only a session id, so it showed as "Session c513a7b6" with nothing about its topic. Now shows only what is working and a short "On your Mac" list; All groups by day; search matches titles first. The owner wants sessions to be easy to find: named by what they are about, described in a sentence, kept up to date on demand, and the one they were just using on the Mac within reach.

## Goals

- **Last on your Mac:** the iTerm2 session that was in front the last time the owner used the Mac is the first row of Now.
- **Pin:** pin and unpin a session from the phone; pinned sessions sit at the top of Now.
- **Names and descriptions:** every session gets a short title and a one or two sentence description, made by a cheap model, automatically once and on demand ("Update summary"), editable by the owner. Shown in rows (a quiet second line), the info sheet, and matched by search. Shared by the TUI, the local dashboard and both phone clients through aimux's existing session metadata.
- **Folders on Now:** project groups read as folders (icon, bold name, guide line), not as sessions.
- Bring aimux's titler up to date: current models, a working `auto_title`, a fallback that needs no API key.

## Non-goals

- Semantic search, embeddings, or tags generated by the model.
- Renaming or describing from the TUI or dashboard (they show the values; editing stays on the phone and in the existing TUI note/annotation flows).
- Grouping All by folder.

## Anti-goals

- Overwriting a title or description the owner wrote.
- Sending conversation text anywhere without the owner's switch on.
- A model call per page view or per poll.

## Constraints

- Metadata lives where it lives today: `history.Meta` in the sidecar `.meta.json` next to each transcript (`LoadMeta`, `SaveMeta`, merged by `history.Discover`). New fields are additive and optional.
- Models: Anthropic only, latest family: `haiku` → `claude-haiku-5-5` (default), `sonnet` → `claude-sonnet-5-5`, `opus` → `claude-opus-5-5`; any other name falls back to the default with one log line.
- Credentials: an API key from `sessions.api_key` or the environment when set; otherwise `claude -p --model <id>` with the owner's existing Claude Code login. aimux never reads, prints or stores a key it did not already have.
- Privacy: titling and describing send up to about 2,000 characters of the session's turns to Anthropic. Automatic runs only when `sessions.auto_title` (titles) and `sessions.auto_describe` (descriptions, new, default follows `auto_title`) are on. On-demand runs are explicit actions by the owner.
- Remote API changes are additive; device login applies to every new route; audit lines carry no text.
- No new dependency.

## Approaches

1. **Extend `history.Meta` and the existing titler, run it from `remote serve` (chosen).** One store and one titler for every front end; the phone triggers on-demand updates through the API. Small, reuses tested code.
2. **A separate phone-only store and summariser.** Faster to build, but the TUI and dashboard would show different names. Rejected.
3. **Use Claude Code's own session names only.** Not available for most sessions and not editable. Rejected.

## Decided

### Metadata

`history.Meta` gains `Description string`, `TitleBy string` and `DescriptionBy string` (`"model"` or `"owner"`), and `DescribedAt string` (RFC 3339) with `DescribedTurns int` (the turn count it summarised). `Discover` fills `Session.Description`. A value with `By == "owner"` is never overwritten by the model.

### Titler and describer (internal/history)

- One call produces both: a title of 3 to 6 words and a description of at most 2 sentences (about 200 characters), as JSON the code validates; anything else is discarded and logged.
- Input: the first user message plus the most recent turns, up to about 2,000 characters, read from the transcript; never the system prompt or tool output beyond short step targets.
- A title is "useless" and may be replaced when it is empty, only a session id (with or without "Session"), starts with "continue" followed by an id, or is only a slash command.
- Backend order: API key → `claude -p` (timeout 60 s) → skip with a log line.

### remote serve

- A background namer: every 2 minutes, at most 5 sessions per run, newest first, for sessions with at least one finished exchange whose title is useless or whose description is missing (only with the switches on). Errors back off per session (1 h).
- `POST /v1/sessions/{id}/describe` runs the call now and returns the new title and description (409 `owner_set` fields stay; the response says which fields changed). Rate: one in flight per session.
- `PATCH /v1/sessions/{id}/meta {title?, description?, pinned?}` writes owner values (`By = "owner"`) and pin.
- `Session` (list) and `SessionDetail` gain `description`, `pinned`; health gains capability `describe`.
- **Last on your Mac:** when terminal input is on, the server asks the iTerm2 driver every 15 s, only while the Mac's idle time is under 120 s, which session is focused (the guard's existing focus probe), and keeps the last one with its time. `GET /v1/sessions` returns `lastOnMac {id, at}`; nothing is stored on disk.
- Audit: `describe`, `meta_edit`, `pin`, `unpin`, no text.

### Clients (both)

- Now, top to bottom: Last on your Mac (one row, "Last on your Mac · 4 min ago", hidden when unknown or older than 12 hours), Pinned, then today's sections. Folder groups: a folder icon instead of the status dot, the name in semibold, count and chevron, a little more space above, sessions indented under a thin guide line; single-session folders keep the folder icon.
- Rows show the description as a second line (one line, truncated, secondary text) when present.
- Info sheet: title and description with Edit, "Update summary", Pin.
- Long press (iOS) / a row menu (web): Pin or Unpin.
- Search matches titles and descriptions locally first, then the server's full-text search as today.
- Shared fixtures in `api/testdata/clients/` pin the Now ordering with Last on your Mac and Pinned, the row second line, and the folder row shape.

## Builder check: answers (my calls; they override the sections above where they differ)

1. **The namer never names its own runs, and `claude -p` runs isolated.** Automated and subagent sessions (`IsAutomated`) are always skipped. The fallback runs `claude -p` from an empty temporary folder with no tools, no MCP servers and no hooks, using whichever CLI flags allow that (the builder confirms them with `claude --help` and records them); if session saving cannot be turned off, the run is still tagged automated and skipped. The fallback uses the owner's Claude Code plan; at Haiku with at most 5 calls every 2 minutes, that is small.
2. **Only recent sessions are named automatically:** sessions active in the last 14 days. Older ones get named only through "Update summary".
3. **Pin is the existing `Meta.Starred`.** The TUI already calls it pinned; the phone shows the same pins. No new field.
4. **No lost writes.** Every writer of `.meta.json` (TUI, dashboard, controller, titler, server) goes through one helper that takes an exclusive file lock, reads the file again, changes only its own fields, keeps unknown keys, and replaces the file atomically. The namer reads the transcript first and holds the lock only for the write. Older installed aimux binaries may still drop the new fields; accepted, since all front ends ship from this repo.
5. **"Useless" is tested on the title the owner sees** (meta title, else Claude Code's own title, else the first message). When Claude Code's title is fine, the namer writes only the description.
6. **Automatic naming runs only in `remote serve`.** The TUI and dashboard keep their on-demand titling.
7. **Existing titles without `TitleBy` count as model-made** (replaceable only when useless).
8. **`POST /describe` answers 200 with what changed** (owner-set fields are left and listed as kept); 409 `owner_set` only when both fields are owner-set.
9. **Model ids:** the API path uses the full ids from the system's current model list (`claude-haiku-5-5` etc.); if the API answers "model not found", it retries once with the CLI alias (`haiku`) through `claude -p`. Repeated failures show on health as `naming: failing` with a fixed reason, and the info sheet's "Update summary" shows the error, so failure is never only a log line.

## Economy revision (owner: be efficient with tokens; overrides the namer, describer and backend sections above)

Evidence (owner's last 14 days, counted without reading text): 161 interactive sessions, 117 with Claude Code `away_summary` entries (system entries Claude Code writes about 3 minutes after the last message when a session sits idle; short sessions rarely get one: 1 of 13 with 3 or fewer messages); 980 automated sessions, none with one. Claude Code also writes `ai-title` entries (aimux already reads the latest).

- **Description, free:** the latest `away_summary` of the session, read by the history scan (`Session.AwaySummary`; bump the scan cache version). No model call. It updates whenever Claude Code writes a new one.
- **Title, mostly free:** the owner's title if set; else Claude Code's `ai-title` unless useless; else a model title made from the away summary only (about 60 to 100 tokens in), or from the first user message capped at 400 characters when there is no summary.
- **Model calls only for useless titles,** once per session, event-driven (when the history shows a finished first exchange or a new away summary for a session whose shown title is useless), never by polling; batched up to 5 sessions per request.
- **"Update summary"** (on request): a model call that writes both title and description from the first user message plus the last turns, capped at 1,200 characters; the owner's own values stay.
- **Budget:** `sessions.naming_daily_limit` (default 50 sessions per day) for automatic calls; on-request calls are not limited but counted. Health shows `naming {today, limit, failing?}`.
- **Visible cost:** every naming call records its input and output tokens in aimux's cost tracking under the label "naming".
- Sessions without an away summary show no description until "Update summary" is used. Automatic descriptions for sessions opened on the phone stay off for now.

## Our own descriptions (owner: generate them where Claude Code has none; overrides "Sessions without an away summary show no description" above)

- When an interactive session active in the last 14 days has had no new message for 5 minutes, has no Claude Code away summary and no description of ours, the namer writes one (and the title too when the shown title is useless) in the same call. Input: the first user message plus the start of the latest reply, capped at about 800 characters. Batched up to 5 per call, counted against `sessions.naming_daily_limit`, tokens recorded under "naming".
- Automatically once per session; after that only "Update summary".
- Shown description: the owner's; else Claude Code's away summary when it is newer than ours; else ours (`description_by: "model"`).

## Lean revision (owner: very efficient; overrides the automatic triggers, input sizes and budget above)

- **Only sessions the owner sees.** Automatic titles and descriptions are made only for a session that a phone client shows (Now's lists, Last on your Mac, Pinned, or an opened chat) and that has no owner value, no Claude Code away summary and nothing of ours. The clients report shown session ids through the existing list and detail requests (no extra request); the server queues those. No idle rule, no background scan.
- **Once per session;** then only "Update summary".
- **Small calls:** input per session is the first user message plus the start of the latest reply, capped at 500 characters; output capped at 60 tokens per session (a 3 to 6 word title and one sentence); up to 5 sessions per request.
- **Daily limit default 20 sessions** (`sessions.naming_daily_limit`); health shows when it is reached.
- **Free sources first:** owner text, then Claude Code's away summary and `ai-title`; the model only fills gaps.
