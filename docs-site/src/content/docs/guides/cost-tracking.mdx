## How It Works

aimux tracks token usage (input, output, cache read, cache write) per agent and calculates cost using per-million-token pricing. Costs appear on agent cards, in the trace view per turn, and in the stats bar as a total.

## TUI

Press `$` to toggle cost-per-turn display in the trace view. The cost dashboard shows per-project breakdowns.

## Web Dashboard

Agent cards and the list view show CPU%, memory, token counts, and cost. The stats bar header shows aggregate totals. The trace panel shows per-turn cost when expanded.

## Unknown Models

Models not in the pricing table show `$0.00`. To add custom model pricing, submit a PR to `internal/cost/tracker.go`.

## What your sessions spent: `aimux cost`

`aimux cost` reads the ledger, the record the model proxy writes of every model call, and sums it.

```bash
aimux cost                      # the last 24 hours, by session
aimux cost --by model --since 7d
aimux cost --by day --since all
aimux cost --by role --since 7d
aimux cost --session 0b61f1d5   # one session: its id, or the start of it
```

```text
Model calls in the last 24h

SESSION   ASKED AS           SERVED             CALLS  FAILED  IN      CACHED  OUT     COST
0b61f1d5  claude-sonnet-5-5  codex:gpt-6.2-sol  212    3       41.2k   1.4M    18.1k   unpriced
220431f5  -                  codex:gpt-6.2-sol  5      0       ~900    0       ~185    unpriced
total                                           217    3       ~42.1k  ~1.4M   ~18.2k  unpriced
```

| Column | Meaning |
|---|---|
| `SERVED` | The model that answered |
| `ENGINE` | With `--by model`, in place of `SERVED`: the engine that served the row's model: `codex`, `anthropic`, or the name of a named upstream. In the JSON a row has `engines` when its calls named one; `total` and rows written before engines were recorded do not |
| `ASKED AS` | The names the client used when they differ from it. A Claude model name answered by another engine shows here; `-` means it got what it asked for |
| `CALLS`, `FAILED` | Model calls, and how many did not end in an answer |
| `IN`, `CACHED`, `OUT` | Input tokens not read from a cache (those written to one included), input tokens read from a cache, output tokens. A leading `~` on a row's counts means the usage of some of its calls was estimated |
| `COST` | `unpriced`: the counts are real, prices are not applied yet |

What it counts and what it does not:

- It counts model calls that passed the model proxy. A session that talks to its provider directly is not in the ledger, so it is not here. The costs on agent cards and in the dashboard, described above, come from each harness's own transcript and are a separate count.
- Under the table it says what the ledger could not show: calls whose answer carried no token figures (counted as requests, their tokens in no sum; `no_usage` in the JSON), calls with no session (counted in no row and not in the total), lines written by another version of aimux, lines that are not whole, and lines missing from a writer. When any of the last three applies it adds `totals are incomplete`.
- With no ledger yet it says so and names the command that makes the model proxy write one.

With `--by role` the rows are the kinds of work a call was: `main` (a session's main conversation), `subagent` (a subagent's own conversation) and `background` (a call the harness makes outside any conversation). The role is decided when the call arrives, from the request's own marks: a subagent's calls carry its id, and a main conversation names its session in the request. The model plays no part, so a session you moved to a small model is still `main`. A call recorded before roles were written is read by the same rule from what its line does hold, so nothing is left unlabelled. A request does not say which kind of subagent sent it, so all subagents are one row.

`--json` prints the same report with whole session ids. Each row has `asked`, the names the client used, and `models`, the models that answered; with `--by model` the row's key is the served model and `models` is left out. `files` is how many ledger files were read.

A shortened id given to `--session` must fit one session; when it fits more, the command says so and stops. Every failure exits 1, a bad flag value included.
